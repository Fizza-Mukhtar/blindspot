# Reproduction guide

Written for someone starting from a clean machine with nothing installed but Python and
git.

**The headline result needs no API key, no network access, no Docker and no GPU.** Every
model call in the published benchmark is committed to `cassettes/` and replayed
deterministically. That is a deliberate design decision, not a convenience: the organiser
does not supply model credits, so a benchmark whose numbers can only be regenerated by
somebody holding a paid key is, in practice, not reproducible.

---

## 0. Three tiers, so you can stop wherever you like

| Tier | Command | Needs | Time | Cost |
|---|---|---|---|---|
| **1 — the headline result** | `make reproduce-quick` | Python 3.11+ | ~15 min | $0 |
| **1b — everything, incl. ablations** | `make reproduce` | Python 3.11+ | ~40 min | $0 |
| **2 — all the evidence** | `make check && make crosscheck` | Python 3.11+ | ~8–12 min | $0 |
| **3 — regenerate from live models** | `make record` | a Claude subscription **or** an API key | ~3–5 h | see [§6](#6-cost) |

Tier 1 is the one that matters. Tiers 2 and 3 exist so nothing has to be taken on trust.

---

## 1. Requirements

- **Python 3.11, 3.12 or 3.13.** Developed and verified on CPython 3.13.4, Windows 11.
  The test suite and the reproduction path are pure Python with no compiled extensions, so
  they work identically on Linux and macOS.
- **git**, to clone.
- **GNU Make** is convenient but never required — every target is one plain command, listed
  below in case `make` is unavailable (Windows users: `make` ships with
  [ezwinports](https://sourceforge.net/projects/ezwinports/) or Git for Windows).

No Docker. No database. No network calls at any point in Tier 1 or Tier 2 — the sandbox
actively blocks sockets, and a probe that tries to open one is rejected as broken rather
than counted as evidence.

## 2. Setup from a clean environment

```bash
git clone <this-repository> blindspot
cd blindspot

python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell:
.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -e .
```

That installs six pure-Python dependencies: `pydantic`, `PyYAML`, `rich`, `Jinja2`,
`hypothesis`, `pytest`. Exact pinned versions are in
[`requirements.lock`](requirements.lock).

Confirm the environment:

```bash
make doctor          # or: python -m blindspot.cli doctor
```

Expected: every import `ok`, the sandbox reporting `pass`, a non-zero cassette count, 14
tasks, and the case count. Provider will read `replay`, which is correct — that is the
offline default.

## 3. Tier 1 — reproduce the headline result

```bash
make reproduce
```

or, without make:

```bash
BLINDSPOT_PROVIDER=replay python -m blindspot.cli eval \
    --split test \
    --systems self_tests baseline_direct baseline_agent blindspot \
    --ablations \
    --out results/reproduced
python scripts/compare_results.py results/expected results/reproduced
```

**What it does.** Replays every recorded model call from `cassettes/`, re-runs every
generated test in the sandbox against both the candidate implementation and the hidden
reference, re-grades everything from scratch, recomputes the statistics, and then compares
the per-case outcome table against the committed one.

**What you should see.** A results table, followed by:

```
REPRODUCED — N runs matched exactly on 8 outcome columns.
```

**Why it compares per-case and not just the summary.** Two runs can agree on a headline
percentage while disagreeing about *which* cases they got right. That is a reproduction
failure, and it would be invisible in a summary comparison.

**Runtime.** About 15 minutes for `make reproduce-quick` and about 40 for `make
reproduce`, measured on a 2026 laptop. Essentially all of it is sandbox subprocess spawns:
every generated test is executed against the candidate *and* the hidden reference, and every
credited counterexample four more times for the determinism gate. The model calls — the
expensive part in wall-clock and money when run live — are replayed instantly and cost
nothing. **The slow part is the part that cannot be faked**, which is the right thing to be
slow.

If you want a faster signal than either, `make test` proves the whole pipeline end to end
against an offline stub model in well under a minute.

**If it fails.** The script prints every differing cell. The usual cause is an edited prompt
or pipeline: cassettes are keyed on the exact prompt text, so changing a prompt invalidates
them by design. Re-record with Tier 3 and commit the new cassettes and results together.

## 4. Tier 2 — check the evidence behind the result

```bash
make test            # the test suite: offline, deterministic, no credentials
make verify-corpus   # mechanical integrity of every label, plus the corpus lock
make crosscheck      # each reference vs. an independent, spec-blind oracle
make check-docs      # every path, make target and test id named in the docs exists
make triage-audit    # every finding shown to a reader vs. the grader's own verdict
make lint typecheck  # ruff + mypy

make check           # all of the above in one command
```

Without make:

```bash
python -m pytest tests -q
python scripts/verify_corpus.py --json results/corpus_integrity.json
python scripts/label_spec_visible.py --check
python scripts/freeze_corpus.py --check
python scripts/run_crosscheck.py --json results/crosscheck.json
python scripts/check_docs.py --strict
python scripts/triage_audit.py
python -m ruff check src tests scripts && python -m mypy
```

**`make test`** runs the whole pipeline end to end against a deterministic offline stub
model, so orchestration, schema repair, sandboxing, splitting and grading are all proven
without spending a token. The tests worth reading first are
[`tests/test_grader.py`](tests/test_grader.py) — the scoring rule as executable
specification, including the case that proves `assert False` scores zero.

**`make verify-corpus`** asserts, for all 14 tasks: the standard-traceable selftest passes
against the reference and is deterministic; the reference is stdlib-only, clock-free and
seed-free; the generator produces mostly-valid inputs and never crashes the reference;
metadata is complete with a real grounding URL; and `SPEC.md` never leaks the experimental
frame. Then, for every forged case: that each buggy case's stored witness genuinely
separates it from the reference, that each clean case is observationally equivalent to the
reference over the published fuzz budget, and that each case's own tests are green on its
own code. It then checks the corpus against
[`spectrap/CORPUS.lock`](spectrap/CORPUS.lock), a sha256 per file: the benchmark was
frozen before the evaluation ran, and any edit to a specification, reference,
implementation or label since then fails the build rather than quietly improving a
number. What was frozen, and when, is in
[`PREREGISTRATION.md`](PREREGISTRATION.md).

**`make verify-corpus`** also re-derives, by execution, which buggy cases genuinely
violate their specification. `has_defect` comes from differential fuzzing and means
*differs from the reference*; `spec_visible` comes from running the task's
authoritative standard-traced suite against the implementation and means *violates a
stated requirement*. Most of this corpus's defects are the first and not the second,
which is the project's main finding — see the [hot take](README.md#9-hot-take).

**`make check-docs`** walks every Markdown file and verifies that each repository path,
`make` target, CLI subcommand and `pytest` node id it names actually exists. It was
written after the documentation was caught referring to an evidence file that had never
been created, and it now runs as part of `make check`.

**`make crosscheck`** is the corpus auditing itself. Every reference implementation was
independently re-derived from the specification and the cited standard by an author who
never saw it; this differentially fuzzes the two against each other and checks both against
values taken from the standard's own worked examples.

**Runtime.** `make test` ~2–4 min, `verify-corpus` ~4–6 min, `crosscheck` ~2–3 min. All
parallelised across cores.

## 5. Tier 3 — regenerate everything from live models

Only needed to re-record cassettes or rebuild the corpus. **Skip this to reproduce the
published numbers.**

### Model access — pick one

**A. Claude subscription (no API purchase).** The Claude Code CLI in headless mode:

```bash
claude setup-token          # prints a long-lived token; opens a browser
cp .env.example .env        # then put the token in .env:
#   CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat01-...
#   BLINDSPOT_PROVIDER=claude_cli
```

**B. Anthropic API key.** `ANTHROPIC_API_KEY=...` and `BLINDSPOT_PROVIDER=anthropic`, then
`pip install -e ".[live]"`.

**C. OpenAI-compatible.** `OPENAI_API_KEY=...` and `BLINDSPOT_PROVIDER=openai`.

`.env` is gitignored and must never be included in a submission archive (Rule Book #08).
Verify with `git check-ignore -v .env`.

### The pipeline, in order

```bash
python -m blindspot.cli split          # ONCE, before anything else. Refuses to overwrite.
make forge                             # build SpecTrap: model writes impl + its own tests
                                       #   the committed corpus took four passes with
                                       #   different quotas -- the exact commands, and the
                                       #   pass that produced nothing, are in
                                       #   spectrap/PROVENANCE.md
make label-spec-visible                # which "defects" are real spec violations
python scripts/freeze_corpus.py        # re-hash the benchmark after changing it
make verify-corpus                     # prove the labels
make learn                             # archetype memory, dev split only
make record                            # run every system live and re-record cassettes
python scripts/update_readme.py        # regenerate every number in the README
```

**Order matters.** `split` must run before anything is evaluated, and it refuses to
overwrite a frozen split without `--force` — re-drawing a frozen split invalidates every
held-out number.

`make learn` refuses to read the test split and exits non-zero if any learned archetype
mentions a test-split task id.

### Determinism under live models

Live model calls are not deterministic, so a re-record will not reproduce the committed
numbers exactly. That is expected and is why cassettes exist. Everything downstream of the
model — sandboxing, grading, statistics — *is* deterministic: `PYTHONHASHSEED=0`, a
derandomised Hypothesis profile, seeded shuffles, third-party pytest plugin autoloading
disabled, and memory addresses and temp paths scrubbed from all captured output.

> That last one is not hypothetical. On the development machine an unrelated installed
> pytest plugin opened a socket during `pytest_configure`, which the sandbox's network
> block turned into a hard failure of every probe. The judge's machine must not be able to
> change a verdict, so the plugin surface is pinned.

## 6. Cost

`make reproduce` costs **$0** and makes **zero** model calls.

For Tier 3, the exact totals from the recorded run are in `results/summary.json` and in the
cost table in the README, regenerated from it. Two honest notes about that number:

- **Content vs. transport tokens.** Under the `claude_cli` backend, prompts are wrapped by
  the Claude Code harness, which added between 8k and 28k tokens per call on the development
  machine regardless of prompt size. That overhead belongs to the transport, not to
  Blindspot, and folding it into a cost-per-audit figure would overstate every system by
  roughly the same large constant and quietly make the comparison meaningless. The reported
  cost is therefore computed from **content** tokens — the actual prompt and completion
  text — priced at published per-model rates. The backend's raw usage is recorded alongside
  in `provider_input_tokens` / `provider_output_tokens`.
- **A subscription is not metered per call.** Under option A the marginal cash cost is zero;
  the USD column is what the same calls would cost on the pay-as-you-go API.

## 7. What each output file is

| Path | What it is |
|---|---|
| `results/per_case.csv` | one row per (system, case). Every published statistic is recomputable from this file alone. |
| `results/summary.json` | detection and false-alarm rates with Wilson intervals, paired McNemar tests, bootstrap effect sizes, cost |
| `results/RESULTS.md` | the generated results table |
| `results/forge_report.json` | every generated implementation and why it was admitted or rejected |
| `results/corpus_integrity.json` | the 154 corpus checks |
| `results/crosscheck.json` | reference vs. independent oracle, per task |
| `results/expected/` | the committed reference results that `make reproduce` asserts against |
| `trajectories/*.jsonl` | one file per run: every model call, tool response, retry and human checkpoint |
| `trajectories/viewer.html` | self-contained viewer — double-click, no server, works offline |
| `cassettes/**.json` | every recorded model call, with its full prompt and completion |

## 8. Troubleshooting

**`CassetteMiss` during `make reproduce`.** A prompt or the pipeline changed since the
cassettes were recorded. The error names the purpose, model and key. Either restore the
committed prompts (`git checkout src/blindspot/prompts/`) or re-record (Tier 3).

**`make` not found on Windows.** Every target is a single command; run the plain
equivalents given above.

**`claude CLI error: Not logged in`.** Run `claude setup-token` and put the resulting token
in `.env` as `CLAUDE_CODE_OAUTH_TOKEN`. `make doctor` performs a live smoke call and prints
the exact error.

**Tests are slow.** `make test-fast` skips the tests marked `slow`. The full suite spawns
many sandboxed subprocesses by design — that is the component under test.

**A probe reports `error` rather than `fail`.** That is deliberate: a test that cannot call
the code is a broken probe, not evidence about the implementation, and is routed back for
repair instead of being counted.
